# UX-принципы калькуляторов SonoGyn — простота уровня ACR

**Статус:** проект на утверждение. Свой интерфейс и формулировки; интерфейс и тексты ACR не копируются.

## 1. Основные правила

1. **Один логический блок за раз.** На экране — один вопрос (или 2–3 тесно связанных), прогресс сверху.
2. **Условное появление.** Вопрос показывается, только если он влияет на результат в выбранной ветке (спецификация `showWhen`).
3. **Минимум кликов.** Варианты — крупные кнопки; выбор сразу ведёт дальше; числа — один ввод с единицей.
4. **Нет предзаполненных клинических значений.** Начальное состояние каждого признака — «не указано». Значение по умолчанию допустимо только для неклинических настроек (язык, единицы).
5. **«Не уверен»** там, где руководство это предусматривает (O-RADS GC8: выбирается более рискованный признак, с видимой пометкой в результате).
6. **«Не оценено»** — отдельная кнопка; никогда не превращается в «нет».
7. **Быстрая правка.** Цепочка ответов (breadcrumb) всегда видна; нажатие на любой шаг возвращает к нему, последующие ответы пересчитываются, неактуальные — снимаются с пометкой.
8. **Результат — сразу**, как только данных достаточно; подробное обоснование, источники и ограничения — в раскрывающемся блоке.
9. **Неполный результат честный:** «Не хватает: … (возможные исходы: O-RADS 3–5)», без категории.
10. **Минимум справки.** Определение термина — по нажатию «i» и иллюстрация лексикона (собственные схемы, не изображения ACR).

## 2. Экран результата

```
┌──────────────────────────────┐
│ O-RADS 3 · низкий риск        │  ← крупно, статус текстом (не только цветом)
│ Рассчитано движком · v2022    │
├──────────────────────────────┤
│ Ведение: …                    │
│ ▸ Почему так (шаги расчёта)   │
│ ▸ Источники и ограничения     │
├──────────────────────────────┤
│ [В протокол]  [Изменить ответы]│
└──────────────────────────────┘
```

## 3. Mobile

- Управление одной рукой: основные кнопки в нижней трети экрана, крупные зоны нажатия (≥ 44 pt).
- Нижняя панель: «Назад», «Сбросить», «Результат».
- Один экран — один вопрос; свайп назад = шаг назад.

## 4. Web

- Рабочее пространство врача: слева шаги и ответы, в центре текущий вопрос, справа живой предпросмотр результата и текста протокола.
- Клавиатурная навигация (цифры — варианты, Enter — далее, Backspace — назад).

## 5. Доступность и темы

- Видимый фокус, подписи кнопок, статусы текстом (правило a11y проекта).
- Только дизайн-токены `--clinical-*`, проверка light/dark на экране вопроса и результата.
- `prefers-reduced-motion` — без анимаций переходов.

## 6. Черновики

Автосохранение ввода — в существующую модель `doctor_tool_drafts` (RLS owner), без ПДн; восстановление — «Продолжить расчёт?». Отдельным PR после согласования.

## 7. O-RADS — пример потока

1. Применимость (ВЗОМТ / внематочная / перекрут нормального яичника / неовариальное → «вне O-RADS»).
2. Визуализация (яичник не виден → not applicable / O-RADS 0 при ожидаемой визуализации).
3. Менопауза (пре / пост / неясно → возраст; лет после менопаузы).
4. Тип: нормальный / физиологическое / образование.
5. Classic benign? (подтип + проверка дескрипторов: камеры, кровоток) → иначе лексикон.
6. Строение: однокамерное / bilocular (1 перегородка) / multilocular / солидное.
7. Контур, солидный компонент, папиллы (число), тень, color score — только нужные ветке.
8. Размер (наибольший диаметр).
9. Асцит / узлы брюшины (если влияет — для 3–4).
10. «Добавить образование» → мультиочаговый итог по наивысшей категории.
