```
Ветка: chore/safety-net (или отдельный PR от текущей). Опирайся на PLATFORM_SNAPSHOT / docs/architecture.

Сделай по шагам; после каждого блока — diff и жди «ок». Не ломай Vercel/Supabase прод.

   .env* в .gitignore. Секреты в коде — только перечислить, не «чистить историю» без запроса.
2. Health: если /api/health (или аналог) уже есть — улучши проверку Supabase/критичных зависимостей
   без смены контракта клиентов. Если нет — добавь минимальный эндпоинт.
3. CI: не дублируй workflow; дополни пробелы (lint/typecheck/e2e smoke) точечно.
4. docs/BACKUP.md: как бэкапить Supabase (официальный путь) + что делать при инциденте.
   Не вводи Docker Postgres «вместо» Supabase.
5. Smoke: опишись на существующие Playwright (`test:e2e:security`, auth, a11y soft).

Бизнес-логику приёма/калькуляторов не менять. Итог: сделано / проверка / откат.
```
