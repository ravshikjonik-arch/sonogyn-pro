## 2. Протокол: «извлечён текст» ≠ «извлечён медицинский смысл»

Метрика — **30 смысловых проверок**, а не процент совпадения символов. Проверка засчитывается, только если клинически значимая связка сохранилась **в одном фрагменте**:

- **Строка таблицы целиком** — категория EU-TIRADS + риск малигнизации + порог ТАБ; пункт ВОЗ A.x + тип рекомендации («рекомендовано / при определённых условиях / не рекомендовано»).
- **Отрицания** — «не рекомендуется», «не претендуют» не потеряны и не оторваны от предмета.
- **Числа** — десятичные (1.4 / 3.5 / 87.7), диапазоны «2–5%», пороги «>10 mm».
- **Страница** — фрагмент указывает на правильную страницу (для цитирования).
- **OCR-скан** — словарный recall относительно текстовой версии ≥ 95%; ноль слов с подменой кириллицы латиницей («He НИЖе»); строки таблицы штатов не разорваны («Врач УЗД ↔ 1», «296570 ↔ 1»).

Скрипты POC (вне репозитория, `/tmp/sonogyn-poc`): `run_docling.py`, `run_docling_scan_variant.py`, `run_baseline.py`, `score.py`. Одинаковый JSON-формат вывода для всех движков (`items{page,label,level,text}`, `tables{page,rows}`), чтобы RAGFlow оценивался тем же `score.py`.

### Где Docling ошибается (важно для медицины)

1. **ETA Таблица 3:** строки EU-TIRADS 1 и 2 слиты в одну — риск и тактика для «normal» и «benign» перемешаны. Строки 3/4/5 корректны.
2. **ETA алгоритм (рисунок, стр. 4):** текст внутри схемы («EU-TIRADS 5: >10 mm») потерян — **пороги из рисунков-алгоритмов не извлекаются**.
3. **Скан 557н (по умолчанию):** ячейки таблиц пустые; recall 77%.
4. **Скан 557н (`cell_matching`):** recall 99%, связи в таблице штатов восстановлены, но **6 слов с подменой латиницы** («He НИЖе среднего класса») и «1. <2>» → «12» (порча номера сноски / числа).
5. ВОЗ Таблица 1 и КР РАЭ — без смысловых ошибок (13/13).

**Вывод по парсингу:** текстовые КР и таблицы Docling извлекает пригодно; **сканы и рисунки-алгоритмы без ручной проверки в RAG нельзя**. Это подтверждает обязательность статуса `review_required` и ревью врача до публикации.

### RAGFlow — отложено до масштабирования

Ключ в `.env.local` добавлен, подключение к `cloud.ragflow.io` прошло, но **бесплатный тариф запрещает API** (`403 You need to upgrade to a Starter or Pro plan to use an API key`). Скрипт `/tmp/sonogyn-poc/run_ragflow.py` готов к повторному прогону после апгрейда или своего сервера.

**Решение 2026-11-10:** свой сервер RAGFlow и платный Cloud **не поднимаем**. На 100–500 пользователей достаточно Evidence + vault + Docling. RAGFlow — когда появится необходимость масштабировать конвейер разбора PDF / сравнить end-to-end тем же `score.py`. Отдельно при возврате: русский OCR (#1987), таблицы на скане, лицензия MinerU (исторически AGPL).

### Recall: `simple` (как в миграции) vs `russian`

13 запросов врача в начальной форме против фрагментов в косвенных падежах («узловой зоб» → «узлового зоба», «препараты железа» → «препаратов железа», «кофеин» → «кофеина»):

| Конфигурация | Нашла нужный фрагмент | Лишние совпадения |
|--------------|----------------------|-------------------|
| `simple` + `plainto` (текущая миграция) | 2 / 13 | 0 |
| `russian` + `plainto` | **12 / 13** | 0 |
| `russian` + OR по словам | 13 / 13 | много шума |

Скорость `russian` с собственным GIN-индексом — как у `simple` (~2 мс / ~71 мс). Без индекса — 1,7 с (неприемлемо). Английский текст `russian`-конфигурация тоже стеммирует (asciiword → english_stem).

### Медицинские ловушки, найденные тестом

- **Аббревиатуры:** «опухоль щитовидной железы» не находит текст с «ЩЖ» → нужен словарь синонимов/аббревиатур (ЩЖ, УЗИ/УЗД, ТАБ/FNA, МЖ, ЛУ).
- **Омонимия стемминга:** «железы» (орган) и «железа» (элемент) дают один корень `желез` — в режиме OR запрос про щитовидную железу поднимает фрагмент про препараты железа. Поэтому **OR-режим для клинических запросов нельзя**, только AND (+ синонимы).
- **Шкала оценки:** `similarity = min(1, ts_rank_cd × 2)` упирается в 1,0 уже на частых словах (8-й результат — 0,75). В приложении `mergeVaultHits` берёт максимум FTS и косинусной близости — FTS будет систематически перебивать семантику. Нужно слияние по рангу (RRF), а не по сырым оценкам.
- **Номер страницы** RPC не возвращает (`page_start` есть в таблице, но не в выдаче) — для цитирования нужно добавить.

### 4b. Новая версия: `20261110120000_medical_vault_fts_ru.sql` (AD-2 + AD-3 одобрены)

Аддитивно, рядом со старой: колонка `content_tsv_ru` (generated, `russian`) + GIN, построитель запроса `medical_vault_ru_tsquery`, функция `match_medical_vault_chunks_fts_ru` (возвращает `page_start/page_end`, оценка `rank/(rank+1)` без насыщения). Старые `content_tsv` / `match_medical_vault_chunks_fts` не тронуты.

Запрос строится по словам: **(основа `russian` | точная форма) AND (…)**. Точная форма нужна из-за асимметрии стеммера на названиях препаратов: «тамоксифен» → `тамоксиф`, а «тамоксифеном» → `тамоксифен`. На 12 препаратах в косвенных падежах: только основа — 11/12, основа | точная форма — 12/12. Стоп-слова пропускаются, OR между словами не используется.

Тест на второй staging-ветке `staging-fts-ru` (история миграций = prod; применены обе миграции в порядке prod; ветка удалена после теста):

|----------|-----------|
| 13 контрольных запросов (чистый корпус) | **12 / 13**, 0 лишних; не найдено только «ЩЖ» (AD-4) |
| Номера страниц в выдаче | ✅ ВОЗ 13/14, ETA 10/4, РАЭ 1/2 — совпадают с источником |
| Ловушки, права `anon` / `authenticated` на обе функции | ✅ 0 попаданий / запрещено |
| Пустой запрос, только стоп-слова, спецсимволы `& \| ! :* (` | ✅ пусто / безопасно |

Наблюдение: в синтетическом корпусе, где «doppler» встречается в тысячах фрагментов, реальный фрагмент по однословному запросу «Doppler» не попал в top-8 — это вопрос ранжирования (решается слиянием с семантикой), а не полноты.

Приложение (`apps/web/lib/evidence/medical-vault-search.ts`): вызывает `match_medical_vault_chunks_fts_ru`, при ошибке — старую функцию, при ошибке обеих — `[]`. Слияние — `mergeVaultHitsRrf` из `@repo/evidence-retrieval` (RRF, k = 60; при равенстве — семантика впереди; payload/score — семантический, страницы — из любого канала). Цитата получает «стр. N» в `section`. Флаги `EVIDENCE_MEDICAL_VAULT` / `EVIDENCE_MEDICAL_VAULT_FTS` не менялись.

## 5. Rollback-план (проверен на ветке)

Для новой миграции (`20261110120000`):

```sql
drop function if exists public.match_medical_vault_chunks_fts_ru(text, int);
drop function if exists public.medical_vault_ru_tsquery(text);
drop index    if exists public.source_chunks_content_tsv_ru_gin_idx;
alter table public.source_chunks drop column if exists content_tsv_ru;
```

Для старой (`20261105120000`):

```sql
drop function if exists public.match_medical_vault_chunks_fts(text, int);
drop trigger  if exists trg_source_chunks_content_tsv on public.source_chunks;
drop function if exists public.source_chunks_content_tsv_trigger();
drop index    if exists public.source_chunks_content_tsv_gin_idx;
alter table public.source_chunks drop column if exists content_tsv;
```

Удаляет только объекты FTS-миграции. Перед откатом в prod: выключить флаг FTS в приложении (поиск продолжит работать через семантику и адаптеры). Отдельный файл rollback-миграции на этом этапе не создавался (текущая миграция в prod применяться не будет — см. AD-2); текст отката хранится здесь.
