# Отчёт: «Репозитории» в кабинете

**Дата:** 2026-11-05  
**Маршрут:** `/tools/repos` (меню «Справочник» → теперь «Исслед. AI»)

## Что это было

Не «файлы платформы SonoGyn», а **просмотр чужих open-source README** (Awesome, USTri, FetalAgents, Echo-Alpha, Medical Imaging Agent).

Экран брал текст с GitHub (`raw.githubusercontent.com/.../README.md`) и клал его в `<pre>` — поэтому выглядело как **готовый код / файлы репозитория**.

## Почему так вышло

1. При проектировании AI/УЗИ в монорепо клонировали OSS (папки `USTri/`, `FetalAgents/`, …) для анализа — см. `docs/architecture/oss-intelligence-audit.md`, `services/us-ai-worker/docs/REPO_ANALYSIS.md`.
2. Чтобы «открыть в кабинете», сделали витрину `/tools/repos` с дампом README.
3. В меню врача попали даже **Awesome / Awesome Selfhosted** (общие IT-каталоги, не медицина).
4. Локальные гигабайты кода (`USTri` ~1.1 GB) **не** отдаются в UI (исключены из Vercel tracing), но **сырой README** с GitHub показывался целиком.

## Что исправлено (2026-11-05) — вариант A

| Было | Стало |
|------|--------|
| Пункт меню «Репозитории» | «Исслед. AI» |
| Сырой `<pre>` на весь README при открытии | Карточка + дисклеймер; README только по кнопке (краткий markdown, sanitized) |
| Awesome в списке врача | `clinicalVisible: false` (404 по прямой ссылке) |
| Ощущение «код продукта» | Явно: чужой OSS, не калькулятор приёма |

**Статус A:** выполнен и задеплоен (карточки вместо `<pre>`).

## Решение продукта (2026-11-05)

**«Исслед. AI» = помощник врача**, не витрина OSS.

| Что | Куда |
|-----|------|
| Меню «Исслед. AI» | `/ai/consultants` (блок «Помощник · EBM») |
| `/tools/repos`, `/tools/repos/[slug]` | redirect → `/ai/consultants` |
| OSS-карточки в кабинете | убраны из клинического UX |
| Локальные клоны `USTri/` и др. | только R&D / docs, не меню врача |

Каталог `PLATFORM_REPOS` в коде может остаться для внутренних ссылок; в UI врача не показывается.
