# Брифинг врача УЗИ по жалобам (us-prep)

## Решение по MedScribe ([Allmostkill/medscribe](https://github.com/Allmostkill/medscribe))

Код MedScribe **не вшит** в SonoGyn Pro: лицензия **AGPL-3.0** потребовала бы открыть связанный продукт / держать изолированный sidecar. Вместо этого реализована **продуктовая формула** под SonoGyn:

| MedScribe (оригинал) | SonoGyn us-prep |
|---|---|
| Памятка / протокол для пациента | **Не генерируется** |
| Черновик протокола приёма | **Брифинг только для врача УЗИ** |
| STT T-one (Docker) | Браузерный голос + опционально `@repo/clinical-speech` позже |
| LLM → текст приёма | Правила сценариев + локальный каталог КР |

## Роли врача (одна платформа)

Врач выбирает роль на приёме — чеклист разный:

| Роль | `role` | Что видит |
|------|--------|-----------|
| Акушер-гинеколог | `obgyn` | Клиника, анализы, маршрут · без полного УЗИ-чеклиста |
| Врач УЗИ | `us` | Вопросы к протоколу УЗИ · без назначений лечения |
| АГ с правом УЗИ | `obgyn_us` | Клиника + УЗИ компактно |

Роль сохраняется в `localStorage` (`sonogyn:us-prep-role`).

## Сценарий на приёме

1. Выбрать роль → открыть `/ai/consultants/us-prep` → **«Включить · слушать приём»**.  
2. Приложение слушает жалобы пациентки (STT).  
3. Движок берёт **один главный сценарий** (priority) → сухой чеклист под роль.  
4. Пациентка экран не видит.

**Пока не тянет** полный каталог нозологий помощника — только сценарии `us-prep-briefing` + локальный каталог КР. Связка с нозологиями — следующий шаг.

## Что видит врач

1. **Сейчас обратить внимание** (главный блок во время приёма)  
2. Вопросы, на которые нужно ответить на УЗИ  
3. Анализы / мазки (контекст)  
4. Лечение / маршрутизация **по КР** (не назначение из модуля)  
5. Ссылки на IDEA / O-RADS / FMF / guidelines  

`audience: doctor_only`, `patientVisible: false`.

## Точки входа

- UI: `/ai/consultants/us-prep`
- API: `POST /api/ai/us-prep-briefing`
- Engine: `lib/ai/us-prep-briefing.ts`

## Не делать без отдельного OK

- Не копировать исходники MedScribe в monorepo  
- Не добавлять кнопку «памятка пациентке» на этот экран  
- Не деплоить без медицинского ревью формулировок сценариев  

## Возможный sidecar позже

Если нужен полноценный локальный STT T-one — запускать MedScribe **отдельным** Docker на машине врача и принимать только обезличенный текст жалоб в us-prep API. AGPL остаётся на sidecar.
